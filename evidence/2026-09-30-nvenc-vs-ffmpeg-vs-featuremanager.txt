#
#     These mangled symbols exist ONLY in 1.43.4:
#       N5boost3_bi6bind_tIbNS_4_mfi3mf1Ib14FeatureManagerbEENS0_5list2INS0_5valueIPS4_EENS7_IbEEEEEE

#     ...where 1.43.0 has only:
#       N5boost3_bi6bind_tIvNS_4_mfi3mf0Iv14FeatureManagerEENS0_5list1INS0_5valueIPS4_EEEEEE

#
#     i.e. FeatureManager::f(void) -> void   became   FeatureManager::f(bool) -> bool.
#     A predicate went in (or a setter became a predicate). This is on the

#     hard-coded filtered request.

# ============================================================================
# 5. CONCLUSION
# ============================================================================
#
# The regression is NOT in the crack, NOT in library presence, NOT in dynamic
# linking, NOT in GPU visibility, NOT in the FFmpeg build, and NOT in the
# probe code. Every one of those was tested and is identical.
#
# What changed is the server's ENTITLEMENT RESOLUTION: 1.43.4 narrowed its
# feature fetch to a hard-coded five-GUID filter that excludes the hardware
# transcode features, and gave FeatureManager a new bool(bool) predicate.
# The crack patches the *local* is_feature_available/bitset layer; on 1.43.4
# that layer is no longer what gates the hardware path, so the hardware
# capability probe is never entered, libnvidia-encode/libnvcuvid are never
# dlopened, and the slot falls to CPU.
